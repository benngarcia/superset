Workspace teleport · recorded in the dev app

Teleport, filmed

Four screen recordings of the real Superset desktop app. Every frame is what the renderer painted, captured over the Chrome DevTools Protocol and driven by real mouse input. Where a recording waits on a sandbox, static stretches are held for at most five seconds; nothing is drawn, staged, or re-rendered.

Machine → cloud, in 27 seconds

The workspace this feature was built in, with a live Claude pane and 97 uncommitted changes, is teleported to a brand-new cloud sandbox. The recording ends on the destination: the arrival terminal with the restore's own result line, then the Claude pane that resumed from the carried transcript.

The box is created the moment Teleport is pressed and boots while the source is captured; it fetches the default branch over its image's clone instead of cloning; every wait polls once a second.

Keep working while it moves

Cloud → this device, in 14 seconds

The other direction, on the same code path. A cloud sandbox with two files written in it and a Claude session is teleported onto this device: the box, which runs the released host-service, captures and pushes the hidden ref with plain git typed into one of its own terminals; this device makes a worktree for the branch and arrives the same way a sandbox would. The recording ends in the new worktree, with the Claude pane resumed inside it and the two cloud files in the Changes panel.

The device is this workspace's own dev host-service, standing in for a machine: a real remote machine cannot be reached from inside a sandbox. On a signed-in desktop the picker lists your hosts.

A move is a source endpoint and a destination endpoint with one composition between them. A source is any host-service with a checkout; when a host predates the teleport procedures, the same work is typed into its terminal as plain git. A destination is anything that can produce a checkout: a worktree on a host, or a new sandbox. The capture is ordinary git objects behind an ordinary ref, and any checkout that can reach origin can take it.

What is real, and how it was wired

The context-menu item, the dialog, the plan, the capture, the sandbox, the restore, and the resumed agents are the shipped code running in the dev app. The git core underneath is tested against real repositories, including this monorepo's own checkout: a capture of 82 dirty files bundled in under a second and restored byte for byte.

This dev app runs inside a cloud workspace whose dev API cannot start sandboxes. For these recordings a local façade on the dev API's port sent the five cloud procedures the dialog uses to the production API under the sandbox's own credential, and everything else to the dev API. Only the address of those five calls changed; the renderer's CSP also had to admit the real sandbox domain. The machine-to-machine run needs two machines to film; its eight steps are exercised end to end in flow.test.ts.
